# ADR-0013 — Strings and resources

**Status:** Draft, pending owner sign-off · **Date:** 2026-08-08 · **Author:** Staff / Port Architect

## Context

- **161 strings** in one `app/src/main/res/values/strings.xml`.
- **181 `stringResource(...)` / `R.string.…` call sites.**
- **No localization at all** — there is no `values-xx/` directory. The app is English-only today.
- 4 vector drawables: `ic_bible_book` (nav glyph), `ic_notification_reminder`,
  `widget_preview`, `ic_launcher_foreground`.
- `material-icons-core` 1.7.8, a **frozen artifact deliberately outside the Compose BOM**,
  supplying ~6 icons.
- Android-only resource files that stay put: `res/xml/today_widget_info.xml`, mipmaps, themes.

Notably, **many user-visible strings are still awaiting owner tone sign-off** — CLAUDE.md carries
a standing backlog of them across sprints S11, S12, S13, S14, S15, S17, S20, S22, S-D, S-L, the
alt-schedules set, the 5 caption strings and the external-app help caption. The port must not
make that backlog harder to clear.

## Decision

**Compose Multiplatform Resources (`org.jetbrains.compose.resources`), in `shared/ui`.**

```
shared/ui/src/commonMain/composeResources/
  values/strings.xml          ← the 161 strings, format unchanged
  drawable/ic_bible_book.xml  ← the 2 shared vectors
  drawable/ic_notification_reminder.xml
```

Call sites become `stringResource(Res.string.reading_open_hint_blb)` — the same shape, with a
type-safe generated accessor instead of `R`.

**Split by consumer:**

| Resource | Home |
|---|---|
| The 161 strings | `shared/ui` composeResources |
| `ic_bible_book`, `ic_notification_reminder` | `shared/ui` composeResources |
| `widget_preview.xml`, `today_widget_info.xml`, mipmaps, `themes.xml` | `androidApp` `res/` |
| iOS AppIcon, LaunchScreen | `iosApp` asset catalog |
| Notification channel names/descriptions | duplicated deliberately — see below |

**Notification strings are the one deliberate duplication.** `ReminderNotifier` and
`PersistentNotifier` are platform classes that need strings outside a composition. Compose
Resources' non-composable read is a `suspend` call, which is awkward inside a `BroadcastReceiver`.
For the ~6 channel/title strings involved, reading them from each platform's native resource
system is simpler and safer than contorting the shared loader. **The notification *body* is
generated by `ReadingFormatter` in shared code and is not duplicated** — only the fixed chrome
("Today's readings", channel name, channel description, the Feb-29 line). Six strings, listed
explicitly in the task brief, with a comment at each site saying why. Anything beyond those six
goes in the shared file.

**`material-icons-core`:** ⟦VERIFY⟧ **V5** (Build & Release) — confirm a CMP-resolvable coordinate
at a compatible version. If none exists, the ~6 icons in use (`Icons.Filled.DateRange`,
`Icons.Filled.Edit`, `Icons.AutoMirrored.Filled.List`, `Icons.Filled.Settings` and similar) are
cheap to vendor as vector drawables — the project has already done exactly this twice
(`ic_stats.xml`, since removed; `ic_bible_book.xml`, still in use) when icons-core lacked a glyph.
**Vendoring is the low-risk fallback and should be taken without much argument** if V5 is at all
awkward.

## Alternatives rejected

**moko-resources.** Mature, widely used, handles strings/plurals/images/fonts, and — unlike
Compose Resources — gives non-composable access without a `suspend` call, which would remove the
notification-duplication caveat above. Rejected because Compose Resources is first-party, ships
with the framework the project is already committing to, needs no extra plugin, and generates
type-safe accessors. Adding a third-party resource plugin to solve six strings is a poor trade.
**Reconsider if the app is ever properly localized** — moko's tooling for translator handoff is
better.

**Move strings into Kotlin objects (`object Strings { const val … }`).** Rejected. It works and
it is dependency-free, but it forecloses localization entirely and abandons the platform's
pluralization and formatting. The app is not localized *yet*; that is not the same as never.

**Keep Android `R.string` and duplicate a `Localizable.strings` on iOS.** Rejected — 161 strings
duplicated across two files with a standing tone-sign-off backlog is a guaranteed drift vector,
and it would make the owner's sign-off pass twice as expensive.

## Consequences accepted

- **181 call sites change.** Mechanical, high-volume, low-risk. Do it as one atomic task per UI
  module.
- **Test string pins.** A number of tests assert literal user-visible strings deliberately
  (CLAUDE.md repeatedly notes "pinned LITERALLY" and "never computed via the prod formatter" — the
  S16 title pins, the S20 legend labels, the S18 streak explainer, the per-provider hint strings).
  Those pins are load-bearing and must survive: they are how the project detects accidental copy
  changes. Under CMP resources they resolve through the generated `Res` object in
  `runComposeUiTest`; **confirm this works before converting them**, and if it does not, keep the
  affected tests Android-side rather than weakening the pin.
- **Six duplicated notification strings.** Named, bounded, commented. Add them to
  `docs/parity-matrix.md` so the tone sign-off pass covers both copies.
- Compose Resources' generated `Res` object lives in the module that declares the resources, so
  `androidApp`'s Glance widget — which reads ~5 strings via `LocalContext.current.getString(...)`
  in `WidgetContent.kt` — must reach `shared/ui`'s `Res`. Glance composables cannot call
  `stringResource` from Compose Resources. **Practical answer: keep the widget's ~5 strings in
  `androidApp`'s own `res/strings.xml`** and add them to the duplication list above (bringing it
  to ~11). Verify the exact count during the task; do not let it grow silently.
- The tone-sign-off backlog gets slightly easier, not harder: one file to review instead of a
  file plus an iOS one.

## Revisit when

- The app is localized into a second language — revisit moko-resources, and revisit the
  duplicated notification strings (they would then need translating twice).
- V5 resolves for `material-icons-core`.
- Any test string pin cannot be expressed in `commonTest`.
